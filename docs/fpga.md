# Soft Chip and FPGA partition contract

All four named configurations share the hierarchy ratios in `configs/aim.json`. **Only the cluster primitives are RTL today**. AIM_FULL is a metadata target and cannot be elaborated as an entire RTL top; materializing 2 million parallel PEs on FPGAs would require very large hardware fleets. Logical hierarchy must be time multiplexed on the emulator with virtual cycle timestamps. AIM_MULTI_FPGA is an architectural configuration, not an integrated hardware implementation.

Partition boundary: cluster/supercluster/die. Packet header proposal: `{version:4, type:4, src:16, dst:16, tag:16, virtual_cycle:64, length_bytes:24, crc:32}` followed by payload; little endian wire serialization and per-virtual-channel sequence IDs. Types: command, DMA request/response, tensor tile, reduction, barrier, credit, reset. Each endpoint holds a credit counter, buffers whole packets and acknowledges barriers; separate channels prevent DMA responses from deadlocking behind requests. Deterministic event ordering: virtual cycle, source ID, sequence. A partition cannot advance past a global barrier until all inbound timestamps are accounted for. This protocol is **proposed**, not implemented in RTL. A prototype can use Ethernet/PCIe links with FPGA vendor-specific transport; the architectural message interface stays the same.

`partition_penalty()` counts message latency and serialization using measured physical link numbers supplied by the user. Example: 100 Gb/s, 2 us latency: 2 KiB incurs 2.164 us per message minimum. Different partition counts change local/remote traffic and simulation speed, not silicon peak FLOPs. Hardware emulator should keep an explicit `virtual_cycle` separate from FPGA physical clock; otherwise link stalls corrupt silicon timing estimates.

FPGA flow: instantiate a small `aim_tensor`, `aim_vector`, `aim_sram`, `aim_dma`, `aim_control`, `aim_packet_switch`; verify them independently; add a tiled cluster top and memory endpoint; run FPGA resource synthesis; then bring up framed transport; finally add distributed event synchronization. `scripts/synth.ys` synthesizes only tensor engine for open-source flow; FPGA-specific project files and multi-FPGA integration are outstanding.
